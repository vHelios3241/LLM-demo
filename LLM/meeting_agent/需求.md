「第二大脑」智能会议系统
一、项目背景
开会容易，会后难。一场半小时的会，往往要再花二十分钟重听录音、整理纪要、一条条扒待办——既费时间，又容易漏掉关键事项和紧急任务。
本项目想做一个「会议第二大脑」：用户把录音丢进去，系统自动听、自动总结、自动列待办，遇到紧急事项还会主动提醒。
二、目标用户
经常开会、会后需要整理产出的人——管理者、项目经理、产品、运营等。
典型场景：开完一场例会，不必重听录音，几分钟后就能拿到这场会讲了什么、有哪些待办、哪件事最急。
三、核心价值
● 省时间：自动转写 + 自动摘要，免去重听录音。
● 不漏事：待办结构化提取，逐条可查、可回看。
● 不误事：紧急事项自动提醒，不会再被埋没。
四、用户故事
1. 作为参会者，我希望注册一个账号并安全登录，这样我的会议数据是私有的、只属于我。
2. 作为参会者，我希望上传一段会议录音后系统自动处理，不用我手动去转写、去总结。
3. 作为参会者，我希望随时看到每场会议的摘要和待办清单，省去翻录音的麻烦。
4. 作为参会者，我希望会议里紧急的事能被识别并及时提醒我，避免错过。
5. 作为参会者，我希望随时回看历史会议列表和待办，知道每场的处理进度。
五、功能需求
5.1 账号系统
● 用户可用「用户名 + 密码」注册账号。
● 注册后可登录；登录获得身份凭证，之后的操作都需要凭证。
● 密码不得明文存储。
5.2 会议录音上传
● 支持 .mp3 / .wav 格式的录音上传。
● 上传后系统保存录音文件，并建立一条「处理中」的会议记录。
● 处理是异步的：上传后用户不必一直等待，可以稍后回来看结果。
5.3 自动语音转写
● 录音上传后，系统自动把语音转成文字。
● 用户无需手动触发转写。
5.4 智能摘要与待办提取
● 系统自动生成一段会议摘要：用几句话讲清楚这场会讲了什么。
● 系统自动提取待办事项，结构化、逐条列出。
● 摘要和待办保存到这场会议的记录里，供用户查看。
5.5 紧急事项提醒
● 系统判断这场会议是否包含紧急 / 高优先级任务。
● 一旦判断为紧急，自动发送外部通知（邮件 / 飞书 / 钉钉之一）提醒用户。
5.6 历史会议查询
● 用户可查看自己所有历史会议的列表，并看到每场的处理状态：处理中 / 已完成 / 失败。
● 用户可查看单场会议的详情：摘要 + 待办清单。
六、非功能需求
● 异步处理：转写与分析较耗时，必须后台处理，不能让用户在前端干等。
● 健壮性：转写或分析失败时，会议状态标记为「失败」，不影响其他会议、不拖垮系统。
